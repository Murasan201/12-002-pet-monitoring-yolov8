# 技術検討レポート

## 対象

Raspberry Pi 上での物体検出（YOLO＋AIアクセラレータ）結果を用いて、サーボ駆動のパン・チルト機構で犬／猫を追従する機能について、**追従方法（フィードバック制御）**を検討する。特に、非リアルタイムOS（Linux）環境で安定した挙動を得るための **デッドバンド**および **角度制限（角度変化量・角速度制限）**の設計思想を重点的にまとめる。

---

## 1. 背景と課題

### 1.1 システム概要

* 入力：カメラ画像
* 推論：YOLO により犬／猫を検出し、バウンディングボックス（bbox）中心座標を得る
* 出力：サーボ角（パン／チルト）
* 目標：検出対象の中心が画面中心に近づくようにカメラ向きを調整する

### 1.2 制御上の制約（Linux＋画像推論）

* 推論処理時間・フレーム周期が一定ではない（サンプリング周期にジッタがある）
* 画像検出結果はフレームごとに揺らぐ（bbox中心が微小に変動）
* SG90 等の小型サーボは内部に位置制御（ブラックボックス）を持ち、外部の急峻な指令で発振・振動が起きうる

上記より、厳密な割り込みベースの定周期制御（PID）をそのまま適用すると、

* ジッタ＋遅延による不安定化
* ノイズに対する過剰応答
* I項によるワインドアップ

などのリスクが高い。

---

## 2. 追従制御方針

### 2.1 基本方針：簡易P制御

画面中心と検出対象中心の誤差を用いた比例制御を基本とする。

* 画面中心：`(cx, cy)`
* 対象中心：`(ox, oy)`（bbox中心）
* 誤差：`ex = ox - cx`、`ey = oy - cy`

パン方向の角度更新（例）：

* `Δθ_pan = Kp_x * ex`

ただし、上記をそのまま適用すると「微小誤差で常時カタカタ」「大誤差で急峻に回して発振」になりやすい。

このため、**デッドバンド**と**角度制限**を組み合わせ、P制御を現実のハード・推論ノイズに適応させる。

---

## 3. デッドバンド（Deadband）の検討

### 3.1 定義

誤差が一定範囲内であれば「十分中心にいる」とみなし、制御出力を 0 とする。

* `|ex| < Db_x` のとき `ex_eff = 0`
* `|ey| < Db_y` のとき `ey_eff = 0`

### 3.2 導入目的

1. **検出ノイズへの過剰応答を抑止**

   * YOLOのbbox中心はフレームごとに数px〜数十px揺れる
   * その揺れに追従するとサーボが常時微振動し、見た目・消費電力・寿命に悪影響

2. **追従の見た目を安定化**

   * 「中心付近では止まる」挙動が、人間にとって自然

3. **OSジッタ耐性の向上**

   * 周期が乱れても、微小誤差の領域で制御が働かないため、破綻しにくい

### 3.3 設計指針（目安）

* 画面幅・高さに対する割合で決める

  * `Db_x = 0.03〜0.05 * image_width`
  * `Db_y = 0.03〜0.05 * image_height`

例：640×480 の場合

* `Db_x ≈ 20〜32 px`
* `Db_y ≈ 15〜24 px`

### 3.4 注意点

* デッドバンドが大きすぎると「追従しない」印象になる
* 小さすぎると微振動が復活する

---

## 4. 角度制限（角度変化量／角速度制限）の検討

### 4.1 定義

1フレーム（1更新）での角度変更量に上限を設ける。

* `Δθ = Kp * e_eff`
* `Δθ_lim = clamp(Δθ, -Δθ_max, +Δθ_max)`

さらに安全稼働域（サーボ可動域）の範囲に角度をクランプする。

* `θ = clamp(θ + Δθ_lim, θ_min_safe, θ_max_safe)`

### 4.2 導入目的

1. **大誤差時の急峻な指令を抑止**

   * P制御は誤差が大きいほど出力が大きくなる
   * そのままでは「一気に最大角へ」「オーバーシュート」「反転」「振動」につながる

2. **サーボ内部制御との干渉を低減**

   * SG90等のサーボ内部にも位置制御がある
   * 外部が大きな目標角を頻繁に更新すると、内部ループと外部ループが喧嘩して発振しやすい

3. **周期ジッタの影響を吸収**

   * 制御周期が短い・長いが変動しても、1回の変化量に上限があることで挙動が破綻しにくい

### 4.3 設計指針（目安）

* SG90クラス（小型・軽負荷）では、まず以下を推奨

  * `Δθ_max = 2〜4 deg / update`

下位（サーボ駆動ライブラリ側）で「少しずつ動かす」設計が既にある場合でも、
上位P制御で `Δθ_max` を設けることで、

* 上位の"意思決定"が荒くならない
* 目標角の更新が常に最大速度にならない
* デッドバンド近傍で自然に減速する

といった効果が得られる。

### 4.4 角度制限の種類（推奨整理）

* **上位（画角P制御）**：角度変化量制限 `Δθ_max`
* **下位（サーボ制御ライブラリ）**：スムージング（補間）・更新周期の統一

役割分担：

* 上位：どれくらい動かすか（制御の意味づけ）
* 下位：どう動かすか（ハード保護・安定実行）

## 5. 推奨制御アルゴリズム（擬似コード）

```python
# Inputs
#  - ox, oy: detected object center (pixels)
#  - cx, cy: image center (pixels)
# States
#  - theta_pan, theta_tilt: current servo angles

# Tunables
Db_x = int(0.04 * W)      # deadband px
Db_y = int(0.04 * H)
Kp_x = 0.01               # deg/px (initial)
Kp_y = 0.01
Dtheta_max = 3.0          # deg/update

# 1) error
ex = ox - cx
ey = oy - cy

# 2) deadband
if abs(ex) < Db_x:
    ex = 0
if abs(ey) < Db_y:
    ey = 0

# 3) P control
d_pan  = Kp_x * ex
d_tilt = Kp_y * ey

# 4) angle step limiting
d_pan  = max(-Dtheta_max, min(Dtheta_max, d_pan))
d_tilt = max(-Dtheta_max, min(Dtheta_max, d_tilt))

# 5) update with safety clamp
theta_pan  = clamp(theta_pan  + d_pan,  PAN_MIN_SAFE,  PAN_MAX_SAFE)
theta_tilt = clamp(theta_tilt + d_tilt, TILT_MIN_SAFE, TILT_MAX_SAFE)

# 6) send to low-level servo library (which may smooth motion)
servo.set_angles(theta_pan, theta_tilt)
```

## 6. チューニング手順（推奨）

### 6.1 まず「パンのみ」で成立させる

* 可動1軸に限定し、追従挙動の安定を優先

### 6.2 デッドバンドを先に決める

* 目標：中心付近でカタカタしない
* `Db_x` を 15px → 25px → 35px と変化させ、微振動が消える点を採用

### 6.3 `Δθ_max` を小さめに設定

* 2°/update から開始
* 追従が遅すぎる場合のみ 3°→4° と増やす

### 6.4 Kp を最後に調整

* 原則：`Δθ_max` に当たりすぎない程度
* 追従が鈍い場合のみ Kp を上げる

（目安）

* 画面幅が 640px の場合、`ex=320px`（端にいる）で `Δθ_max` に到達するようにすると安定

  * 例：`Δθ_max=3°`なら `Kp ≈ 3/320 ≈ 0.0094 deg/px`

---

## 7. 想定される失敗モードと対策

1. **中心付近でカタカタする**

   * 対策：`Db` を増やす、`Kp` を下げる、下位ライブラリのスムージングを強める

2. **追従が遅すぎる**

   * 対策：`Δθ_max` を増やす（先）、それでも不足なら `Kp` を増やす

3. **行き過ぎて振動する（ハンチング）**

   * 対策：`Δθ_max` を下げる、`Db` を少し増やす、`Kp` を下げる

4. **検出が途切れたときに暴れる**

   * 対策：検出ロスト時は角度保持、もしくはゆっくりセンター復帰（別途仕様化）

---

## 8. 結論

* Raspberry Pi（非RT OS）＋YOLO（推論ジッタ・検出揺らぎ）＋小型サーボ（内部制御あり）の条件下では、厳密な定周期PIDよりも、
  **P制御をベースにデッドバンドと角度制限を組み合わせた設計**が安定性・再現性・実装容易性の点で適している。

* デッドバンドは「中心付近で動かさない」設計であり、検出揺らぎに対する微振動を抑え、見た目の安定を大きく改善する。

* 角度制限は「急に動かさない」設計であり、サーボ内部制御との干渉を低減し、ジッタ環境でも破綻しにくい挙動を実現する。

* 下位ライブラリ側でのスムージングが既にある場合でも、上位P制御で角度制限を設けることで、意思決定の粗さを抑え、追従の自然さと安定性をさらに向上できる。

---

## 付録：用語

* デッドバンド：誤差が小さい範囲では制御出力を0とする帯域
* 角度制限（角度変化量制限）：1回の更新で変化させる角度の上限
* 安全稼働域：ハード評価により算出したサーボの安全可動範囲
